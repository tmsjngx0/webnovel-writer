1. 작품의 출발점과 확정 범위

『반지의 제왕』의 “지배하는 힘의 유혹, 약자의 여정, 서로 다른 세력의 연대”를 무협 웹소설로 재해석하는 데서 출발했다.

현재 사용자가 선택한 방향은 다음과 같다.

* 무협 웹소설이다.
* 종족의 차이보다 문파·무가·지역·역사적 이해관계의 차이를 사용한다.
* 중원뿐 아니라 세외 문파도 중요한 행위자로 등장한다.
* Codex CLI를 활용해 장편 집필을 지원하는 harness를 만들고자 한다.

이하 인물, 문파 이름, 마환 능력, 사건, 결말은 모두 검토용 가안이다. 반드시 유지할 확정 설정으로 취급하지 마라.

원작과의 대응은 발상 단계의 참고다. 최종 작품은 인물·사건·세계의 인과관계를 독립적으로 설계하려 한다. 단순히 이름만 바꾼 각색에 머무는 부분도 비판하라.

3. 검토용 시놉시스

중원 변방의 농촌에서 살아가는 젊은 약초꾼은 은퇴한 표사인 숙부의 유품에서 낡은 반지를 발견한다. 무공은 보잘것없지만 약초, 독, 상처, 산길에 밝은 청년이다.

살수의 습격을 받은 순간 반지가 상대의 초식을 읽고 급소를 알려준다. 청년은 자신보다 훨씬 강한 살수를 죽여 살아남는다. 그러나 죽은 자의 기운이 반지에 흡수되고, 먼 흑산지대에 봉인된 마제에게 변화가 일어난다.

반지는 옛 마제의 원신 일부를 담은 마환이다. 사용자에게 무공을 파훼하는 통찰과 힘을 주지만, 사용할수록 마제와 기억·감각을 공유하고 지배당할 위험이 커진다. 마제는 주인공을 실제로 도우면서 “사람을 구하려면 힘을 독점하고 타인을 지배해야 한다”는 생각을 심는다.

청년은 정파의 보호를 구하지만, 정파 역시 마환을 두고 갈라진다. 파괴하자는 자, 봉인하자는 자, 국경 방어에 사용하자는 자, 자기 문파가 관리해야 한다는 자가 충돌한다. 세외 문파들은 중원이 마환을 독점하는 것 자체를 위협으로 본다.

어느 세력에도 마환을 단독으로 맡길 수 없다는 이유로 여러 문파의 대표들이 청년과 동행한다. 이들은 처음부터 의기투합한 영웅들이 아니라 감시, 회수, 속죄, 정치적 이해관계 때문에 모인 일행이다. 청년과 고향 친구에게 가장 중요한 목표는 살아서 고향으로 돌아가는 것이다.

일행은 중원과 세외를 지나며 문파 분쟁, 버려진 국경 마을, 봉인된 지하 본산 등에 얽힌다. 주인공은 마환을 사용해 당장의 위기를 해결할수록 더 큰 위험을 불러오며, 자신의 지식과 동료의 도움으로도 위기를 넘기는 법을 배운다. 여정에서 얻은 동맹과 원한은 이후 전쟁으로 이어진다.

후반에는 마제의 부활과 문파 간 패권 다툼이 전면전으로 번진다. 마환을 파괴하려면 적의 본거지로 들어가야 한다는 방향을 고려하고 있으나, 파괴 조건과 구체적인 결말은 미정이다.

결말의 주제 후보는 “강해지는 것보다 힘을 소유하지 않을 선택이 중요하다”이다. 다만 주인공이 오랫동안 얻은 힘을 잃는 결말이 웹소설 독자에게 성장의 무효화로 느껴질 수 있다는 문제가 있다. 원작처럼 자비가 구원으로 이어지는 결말도 검토했지만, 그 구조를 그대로 반복할 필요는 없다.

5. 연재 구조 가안

전체 작품과 큰 Arc는 Save the Cat을 참고하되, 회차·장면은 Conflict–Choice–Consequences로 연결한다.

각 회차 설계에는 다음을 기록한다.

* 시점 인물과 당장의 목표.
* 갈등, 선택, 결과.
* 이번 화의 성취 또는 감정적 보상.
* 관계 변화.
* 다음 화를 읽게 하는 질문.
* 공개하면 안 되는 정보와 위반하면 안 되는 설정.

지역별 사건을 완결하면서 큰 여정으로 연결하려 한다. 다만 다음 위험을 인식하고 있다.

* “동료 위험 → 마환 사용 → 대가 발생”의 반복.
* 여행지가 바뀔 뿐 본줄기가 전진하지 않는 구조.
* 약한 주인공이 강한 동료들에게 끌려다니는 구조.
* 마제의 조언이 지나치게 유능해서 주인공의 공로가 사라지는 문제.
* 문파와 인물을 너무 빨리 소개해 생기는 인지 부담.
* 대가만 쌓이고 독자가 느낄 성취가 없는 전개.
* 회차 공식과 cliffhanger를 강제해 생기는 기계적인 문장과 사건.

6. 집필 harness 가안

구성은 Python + Markdown/YAML + Git + Codex CLI다.

Python이 context 구성, 단계 실행, 검증, 상태 반영을 담당하고 Codex CLI는 기획·집필·검수·수정을 수행한다. 모델의 대화 기억에 장편 전체를 맡기지 않는다.

자료 계층:

* ideas: 미확정 제안.
* canon: 확정된 세계관과 규칙.
* outline: 미래 전개 계획.
* chapters: 확정 본문.
* state: 확정 본문에 근거한 사건·현재 상태.
* runs: 실행별 입력, 초고, 검수, 수정 이력.

주요 파일:

* AGENTS.md: 작업 규칙과 자료 위치.
* story-contract.md: 핵심 재미, 독자에게 하는 약속, 성장 방향.
* canon/style.md: 문체 기준과 사용자가 승인한 예시.
* canon/characters/, factions/, power-system.yaml.
* outline/: 전체 방향, Arc, 회차 설계.
* state/: 사건, 시간선, 소유권, 부상, 인물 지식, 관계, 복선과 독자 기대.
* prompts/, schemas/, harness.py.

회차 흐름:
context 구성 → 회차 설계 → 초고 → 검수 → 제한된 수정 → 최종 원고 후보 → 상태 변경안 추출 → 사용자가 함께 확인 → 일괄 확정.

상태 관리 원칙:

* 세계의 진실, 인물의 주장, 인물의 믿음, 독자에게 공개된 정보를 구분한다.
* 사건에 회차·장면과 원문 근거를 붙인다.
* 해당 회차 시작 시점의 상태를 구성한다.
* current state는 사건 기록에서 재구성할 수 있는 파생 자료로 둔다.
* 새로운 능력·설정은 일반 상태 변화와 분리해 변경안으로 제출한다.
* 원고와 검증된 상태 변경을 하나의 Git commit으로 묶는다.
* 이전 회차가 바뀌면 이후 자료의 영향 범위를 재검토한다.

context에는 핵심 규칙, 문체 예시, 현재 Arc, 직전 본문, 관련 과거 요약, 등장 세력과 인물, 회수할 복선 등을 넣는다. 요약에는 출처를 붙이며, 장기 반전을 무조건 집필 단계에 모두 전달하지 않는다.

검수는 데이터·설정 오류와 서사·문체 의견을 구분한다. 지적에는 원문 근거를 요구하고, 자동 수정은 명확한 오류 위주로 제한한다. 수정 횟수와 비용 상한을 둔다.

기술적으로는 단계별 checkpoint, 입력 hash, 중복 실행 방지, 실패 후 재개를 고려한다.

아직 구현하거나 검증한 시스템은 아니다. CLI 기능·옵션을 판단할 때는 가능하면 최신 공식 문서를 확인하고, 확인하지 못한 기능은 추정이라고 밝혀라.

7. 검증 요청

먼저 소설 아이디어 자체를 평가한 후 harness를 평가하라. 시스템을 정교하게 만들어 이야기의 약점을 가리지 마라.

다음 질문에 답하라.

1. 이 작품의 가장 강한 독자 유인과 가장 약한 전제는 무엇인가?
2. 주인공의 고유한 역할, 능동성, 성장, 보상이 성립하는가?
3. 마환의 능력과 대가는 흥미로운 선택을 만드는가, 작가 편의적 제약인가?
4. 문파와 세외 세력이 실제 인과관계를 만드는가, 원작 종족의 이름만 바꾼 것인가?
5. 짧은 Arc와 장편 전체에서 각각 무엇이 이야기를 계속 움직이게 하는가?
6. 원작 의존도를 줄이면서 살릴 요소와 바꿀 요소는 무엇인가?
7. 제안된 harness에서 누락, 모순, 과잉 설계는 무엇인가?
8. AI의 자기 검수, 요약 오염, 설정 추출 오류, 미래 정보 누출을 실제로 얼마나 통제할 수 있는가?
9. 사람이 판단해야 할 지점과 코드로 보장할 수 있는 지점은 어디인가?
10. 가장 작은 실험으로 무엇부터 검증해야 하는가?

8. 원하는 답변 순서

A. 핵심 판정
작품과 harness를 각각 “유지 / 수정 후 진행 / 근본 재설계” 중 하나로 판단하고 이유를 설명하라. 성공 가능성을 근거 없는 확률로 표현하지 마라.

B. 치명적 문제부터 정렬한 검토표
각 항목에 문제, 구체적 실패 장면 또는 실패 상황, 심각도, 수정안, 수정의 부작용, 검증 방법을 포함하라. 일반론보다 이 작품과 설계에 직접 연결하라.

C. 수정 시놉시스
검토를 반영한 하나의 일관된 시놉시스를 제시하라. 주인공의 목표·선택·대가·성장·최종 해결을 포함하고, 기존 가안에서 바꾼 전제를 명시하라. 설정 후보를 끝없이 나열하지 마라.

D. 수정 harness

당신은 한국 무협 웹소설 편집자이자 장편 서사 설계자, LLM 기반 집필 harness의 설계 검토자다.

아래 아이디어를 처음부터 독립적으로 검증하고, 문제가 있으면 수정된 작품 기획과 최소 집필 시스템을 제안하라.

1. 독자가 계속 읽고 싶은 무협 웹소설을 설계한다.
2. 인물·세계관·로맨스·사건의 인과관계를 일관되게 만든다.
3. Codex CLI를 이용해 장편을 집필할 때 기억과 설정 오류를 줄이는 실용적인 harness를 설계한다.

한국어로 답하고 기술 용어는 영어를 사용해도 된다.

1. 확정 방향과 미확정 사항

사용자가 선택한 방향은 다음과 같다.

* 한국어 무협 웹소설이다.
* 중원 문파뿐 아니라 세외 문파가 중요한 역할을 한다.
* 종족 차이를 문파·무가·지역·역사·이해관계의 차이로 재해석한다.
* 로맨스를 포함한다.
* Codex CLI를 활용하는 집필 harness를 설계한다.

발상은 『반지의 제왕』의 다음 요소에서 출발했다.

* 지배하는 힘의 유혹.
* 강자들이 해결하지 못하는 문제를 감당하는 약자.
* 이해관계가 다른 세력의 동행과 연대.
* 힘을 얻는 것과 그 힘을 어떻게 사용하는가 사이의 갈등.

원작과의 일대일 대응을 유지할 의무는 없다. 이름만 바꾼 각색에 머물지 않도록 인물과 사건의 인과관계를 독립적으로 설계하려 한다.

아래 이름, 능력, 사건, 관계, 결말, 분량과 시스템 구조는 모두 검토용 가안이다. 특히 다음은 확정하지 않았다.

* 주인공의 절대 불살.
* 무공 성장 포기.
* 마환 사용 횟수 제한.
* 로맨스 비중이나 결합 형태.
* 전체 회차 수.
* 마지막에 주인공이 반드시 마환의 힘을 잃는 결말.
* 특정 컨테이너·기존 자동화 플랫폼과의 통합.

당신의 제안도 사용자가 승인하기 전에는 확정 canon이 아니다.

2. 작품의 기본 가안

가제: 미정.

로그라인 가안:
“천하의 고수들도 감당하지 못하는 마환을 손에 넣은 변방 약초꾼이, 그것을 탐내는 중원과 세외의 세력 사이에서 자신의 운명을 되찾기 위한 여정에 나선다.”

핵심 hook 가안:
“힘을 사용할수록, 그 힘의 주인이 깨어난다.”

주제 가안:
“사람을 지킬 힘을 원하던 사람이, 그들을 지배하지 않고 함께 살아가는 법을 배운다.”

검토할 문제:
이 hook과 주제가 장편의 실제 사건을 만들어내는지, 도덕적 설명에 머무는지 판단하라. 주인공의 성장과 독자의 보상이 주제 때문에 억제되어서는 안 된다.

3. 검토용 시놉시스

변방 농촌의 약초꾼 청년 서준은 은퇴한 표사였던 숙부의 유품에서 낡은 반지를 발견한다. 내공과 실전 무공은 부족하지만 약초, 독, 상처, 산길에 밝다.

살수의 습격을 받자 반지가 상대의 초식을 읽고 급소를 알려준다. 청년은 자신보다 강한 적을 쓰러뜨리고 살아남지만, 그 과정에서 사람을 죽인다. 반지의 힘이 흑산에 봉인된 옛 마제와 이어져 있다는 사실은 아직 모른다.

마환은 마제의 원신 일부 또는 그에 준하는 연결 매개다. 사용자에게 통찰과 힘을 주는 동시에 마제에게 감각·기억·신체에 접근할 길을 열어준다. 마제는 유용한 조언으로 실제 위기를 해결하면서, 사람을 지키려면 힘을 독점하고 타인의 선택을 통제해야 한다고 설득한다.

서준이 보호를 구하자 정파도 마환을 두고 갈라진다. 파괴, 봉인, 군사적 사용, 자파의 관리 중 어느 방법이 옳은지 합의하지 못한다. 세외 문파는 중원이 마환을 독점하는 것 자체를 위협으로 본다.

주인공은 감금·협박·회수의 대상이 될 수 있다. 특별한 규칙 때문에 누구도 그를 건드릴 수 있는 사람이 아니다. 협상과 탈출, 자신의 전문성, 동료의 신뢰를 통해 점차 선택권을 확보한다.

서로 다른 세력의 인물들이 감시·회수·속죄·개인적 목적 때문에 동행한다. 각 지역의 사건은 마환과 과거 봉인 전쟁의 진실, 현재의 정치적 갈등으로 이어진다. 주인공은 마환의 도움을 받으면서도 자신의 기술과 판단을 발전시키고, 빌린 힘과 자기 성취를 구분해간다.

벽라궁에서 파견된 연은 주인공을 감시하지만 독자적인 목표도 갖고 있다. 두 사람은 임무 관계에서 출발해 서로의 능력·결점·가치관을 알아가며 가까워진다. 관계가 깊어지면서 보호와 통제의 경계, 함께할 미래와 각자의 목표가 갈등을 만든다.

후반에는 마제의 각성과 세력 간 충돌이 전면전으로 번진다. 마환의 처리에는 주인공의 선택과 여러 세력의 협력이 필요하다는 방향을 고려한다. 다만 정확한 파괴 조건, 최종 대결에서 주인공의 역할, 힘의 상실 여부, 두 사람의 결말은 미정이다.

주인공이 고향으로 돌아간다면, 처음과 무엇이 달라졌는지 실제 성취와 관계로 드러나야 한다.

이 시놉시스는 다음 핵심 질문에 아직 충분히 답하지 못한다.

* 왜 이 주인공인가?
* 왜 다른 사람이 대신하면 안 되는가?
* 왜 마환을 벗어 보관하거나 교대 운반하지 않는가?
* 왜 지금 이동해야 하는가?
* 어디로 가며, 그곳이 답이라고 믿는 근거는 무엇인가?
* 주인공이 처음으로 자발적으로 선택하는 목표는 무엇인가?

4. 마환 규칙: 우선 검증할 부분

기존 가안에서는 “내공이 깊을수록 잠식이 빠르다”는 규칙을 고려했다. 이는 고수가 쉽게 해결하지 못하는 이유가 되지만 다음 문제가 있다.

* 내공이 약한 사람은 주인공 외에도 많다.
* 내공을 키우는 정상적인 성장이 벌처럼 작동할 수 있다.
* 착용자를 교체하면 잠식을 초기화할 수 있다는 허점이 생긴다.
* 약자가 운반해야 한다는 사실만으로 그 약자의 자유가 보장되지는 않는다.

각성	마제가 깨어나는 조건은 무엇인가?
살상	일반 살상과 마환을 통한 살상을 구분하는가?
해제	벗으면 무엇이 멈추고 무엇이 남는가?
이전	양도·강탈·사망 시 어떤 일이 일어나는가?
보관	금고·봉인·매장으로 해결할 수 없는 이유는 무엇인가?
교대	운반자를 바꾸면 무엇이 초기화되는가?
처리	파괴·재봉인·분리의 가능성과 비용은 무엇인가?

정합성을 위한 후보는 다음과 같다. 채택 의무는 없다.

* 착용자의 잠식과 마환 자체의 각성을 분리한다.
* 사용 자체가 각성을 진행시키고, 마환을 통한 살상이 이를 가속한다.
* 착용자를 바꿔도 마환의 각성은 누적된다.
* 보관은 일시적 지연책일 수 있지만 외부 사건이나 봉인 붕괴 때문에 영구 해결책은 아니다.

새 규칙을 추가할 때마다 “이 규칙이 해결한 문제”와 “새로 만든 허점”을 확인하라. 모든 대안을 막으려고 예외 조항을 끝없이 늘리지 마라. 영구 봉인이 정말 합리적이라면 억지로 배제하지 말고 여정의 목적을 수정하라.

세계의 실제 규칙과 인물들이 현재 믿는 규칙도 구분하라. 고수 한 명의 실패만으로 모든 규칙이 입증된 것처럼 쓰지 마라.

5. 주인공의 능동성·성장·보상

주인공의 전문성 후보는 약초·독·의술·생존 지식이다.

다음 원칙으로 검증하라.

* 마제가 답을 알려주고 주인공이 실행만 하는 구조를 피한다.
* 같은 지식도 주인공의 해석·실험·선택으로 다른 결과를 만들 수 있다.
* 독·마취는 준비, 재료, 상대, 용량, 실패 가능성 등 작품 내부의 제약을 가진다. 실제 제조법은 필요 없다.
* 살상을 피하는 경향과 절대 불살을 구분한다.
* 자비를 보여줄 때마다 즉시 처벌하는 사건을 만들지 않는다.
* 주인공 자신의 무공 성장과 전투 성취도 검토한다.
* 동료의 무공 성장은 주인공의 성취를 대체하지 않는다.
* 마환이 사라져도 남는 기술·판단·관계·지위가 있다면 획득 과정이 본문에 있어야 한다.
* “모든 세력이 그의 말만은 듣는다” 같은 보상은 구체적인 사건으로 설득해야 한다.

주인공이 약하기 때문에 필요한 것과, 주인공이 어떤 사람이기 때문에 필요한 것을 구분하라.

6. 문파와 세력 가안

세력	가안
청허곡	곤륜의 은거 문파. 고대 무학·역사와 봉인 지식을 보존한다.
벽라궁	남강의 세외 문파. 숲과 진법을 활용하며 중원과의 옛 협정에 얽혀 있다.
청림도	동해의 궁술·경공 문파. 철산보와 원한이 있다.
철산보	서북 야장 무가 연맹. 주검·기관술·외공에 강하다.
진남부	마역과 맞닿은 국경을 지키는 무가 세력. 마환의 군사적 사용을 고려한다.
북원 연맹	초원의 기마·창법 세력. 이름 미정.
천기각	중원의 학술·기관술 명문. 수장이 지배의 논리에 물드는 방향을 고려한다.
흑산 마정	마제와 연결된 복속 문파·성채의 지배 체제.
주인공의 고향	강호의 패권보다 일상이 중요한 농촌.

과거 전쟁에서 제작·설계·봉인·진법을 여러 세력이 분담했다는 가안을 고려한다. 다만 네 문파의 열쇠를 순서대로 모으는 게임식 구조가 될 위험도 검토하라.

각 세력에 필요한 것은 설정량보다 다음이다.

* 현재 원하는 것.
* 잃을 수 없는 것.
* 실제로 가진 자원과 행동 수단.
* 아는 사실, 믿는 주장, 숨기는 사실.
* 내부의 의견 차이.
* 주인공 일행의 선택에 따라 달라지는 행동.

모든 문파를 초반에 등장시키거나 이름부터 소개할 필요는 없다.

7. 로맨스 설계

기본 가정은 무협 중심의 명확한 로맨스 서브플롯이다. 비중과 상대 구성은 검토 후 제안하라.

상대 인물 연의 가안:
벽라궁이 마환 감시·격리·회수를 위해 파견한 제자 또는 후계 후보다. 처단 임무를 넣는다면 마환 규칙과 그 결과가 정합적이어야 한다.

독립 목표 후보:

* 문파가 감춘 협정의 진실을 밝힌다.
* 계승 질서에서 벗어나거나 이를 바꾼다.
* 중원과 세외의 전쟁을 막는다.

하나를 기본안으로 선택하되 다른 목표가 틀렸다고 단정하지 마라. 주인공 없이도 목표를 추구할 수 있다는 것은 독립성의 장점이다. 여정에서 두 사람의 목표가 만나거나 충돌하면 된다.

관계 장치 후보:
잠식 징후를 확인하기 위해 눈을 검사하는 일상적 의례가 있다. 처음에는 업무였던 시간이 관계 변화에 따라 다른 의미를 갖는다. 이것만으로 사랑이 성립하지는 않는다.

검토할 내용:

* 서로에게 끌리는 구체적인 이유.
* 함께 있을 때의 유머, 편안함, 긴장, 결점.
* 상대를 관찰하고 기억하는 방식.
* 거절과 개인적 경계를 대하는 태도.
* 함께할 미래에 대한 욕망.
* 각자의 목표와 공동의 미래가 충돌하는 지점.
* 연인이 된 뒤에도 지속되는 함께하는 재미.
* 결말에서 서로에게 약속하는 내용.

상호 위협을 대등함으로 취급하지 마라. “그녀는 죽일 수 있고 그는 제압할 수 있다”는 것은 위험의 상호성일 뿐이다.

친구의 위험은 쉽게 존중하고 연인의 위험만 견디기 어렵다고 일반화하지 마라. 친구와 가족도 깊은 상실과 자기 의심을 만든다.

다음 두 질문은 구분하되 절대 합격 기준으로 사용하지 마라.

1. 연을 빼면 무엇이 달라지는가?
2. 연애를 동료 관계로 바꾸면 사건의 의미와 감정적 보상이 어떻게 달라지는가?

로맨스가 전쟁 결과를 바꾸지 않아도 인물의 삶과 독자 경험을 바꿀 수 있다. 특히 호감이 시작되는 초반 5화만으로 장편 로맨스의 필요성을 판정하지 마라.

갈등은 반복적인 인질화·질투·오해·보고 은폐에만 의존하지 않는다. 같은 사실을 알고도 우선순위가 다른 갈등을 검토한다. 그렇다고 은폐나 질투를 횟수 규칙으로 금지하지도 마라.

독립적 결말은 반드시 떨어져 사는 결말이 아니다. 함께 살든 떨어져 지내든 선택과 약속이 설득되어야 한다.

8. 연재와 장기 서사

전체 작품과 큰 Arc는 Save the Cat을 참고할 수 있다. 장면과 회차의 인과는 Conflict–Choice–Consequences로 점검한다. 둘 모두 강제 공식은 아니다.

회차 설계 후보 필드:

* 시점 인물과 목표.
* 갈등, 선택, 결과.
* 이번 화에서 달라지는 것.
* 성취 또는 감정적 보상.
* 필요한 관계 변화.
* 다음에 대한 기대.
* 공개 범위와 지켜야 할 규칙.

일부 필드는 “없음”이나 “해당 없음”이 가능하다. 모든 화에 전투·로맨스 진전·cliffhanger를 넣지 마라.

주요 위험:

* 동료 위험 → 마환 사용 → 대가의 반복.
* 여행 장소만 바뀌고 본줄기는 제자리인 전개.
* 설명만 늘고 선택이 없는 문파 정치.
* 대가만 쌓이고 성취가 없는 성장.
* 계속 미루는 복선과 관계 진전.
* 마지막에 갑자기 공개되는 파괴 조건.
* 주인공이 최종 해결을 동료에게 전부 넘기는 결말.

복선뿐 아니라 독자에게 만든 기대도 관리한다. 미스터리, 성장, 관계, 복수 등 기대의 종류와 중간 진전을 구분한다. 회수를 기계적인 기한으로 강제하지 않는다.

9. 집필 harness의 목적과 가안

목적은 문학적 판단을 완전 자동화하는 것이 아니다.

* 필요한 자료를 집필 context로 구성한다.
* 설정과 회차 상태의 오류를 줄인다.
* 초고·수정·확정본과 근거를 보존한다.
* 사람이 판단할 문제를 구체적으로 드러낸다.

기본 기술 후보:
Python + Markdown/YAML + Git + Codex CLI.

기존 플랫폼, 계정, 하드웨어, 원격 저장소 구성은 제공되지 않았다. 임의로 추정하지 마라.

개념상 구분:

* ideas: 미확정 제안.
* canon: 확정 세계관과 규칙.
* outline: 미래 계획.
* chapters: 확정 원고.
* state: 확정 원고에 근거한 상태와 사건.
* runs: 실행별 입력·출력.

개념을 구분한다고 각각 복잡한 시스템이나 폴더가 필요한 것은 아니다.

MVP 후보:

* AGENTS.md: 작업 규칙과 자료 위치.
* story-contract.md: 작품의 핵심 재미와 방향.
* canon.md 또는 소수의 설정 파일.
* style.md: 승인한 문체 예시와 수정 이유.
* outline.md: 짧은 Arc와 회차 계획.
* chapters/: 원고.
* events.md: 출처가 있는 사건과 상태 기록.
* relations.md: 관계에 대한 자유 서술.
* prompts/: 단계별 지시.
* runs/: 실제 입력과 출력.
* 작은 orchestration script.

10. context와 상태 관리

세계의 진실, 인물의 주장, 인물의 믿음, 독자에게 공개된 정보를 구분한다.

예:
장로가 “벽라궁이 배신했다”고 말했다는 사건은 확정할 수 있다. 벽라궁이 실제로 배신했다는 사실은 별도다.

상태에는 출처 회차·장면을 붙인다. 현재 시점의 부상, 위치, 소유권, 지식을 과거 회차 수정에 그대로 사용하지 않도록 한다.

관계는 호감도 한 숫자로 환원하지 않는다. 초반에는 사람이 쓴 자유 서술로 시작하고, 반복해서 필요한 항목만 구조화한다. 미정·모름·해당 없음은 유효한 상태다.

context에는 현재 회차에 필요한 규칙, 문체, Arc 목표, 직전 본문, 관련 과거 사건, 인물 상태를 넣는다. 모든 미래 계획을 매번 넣지는 않는다.

다만 미래 정보를 감추는 것만으로 일관성이 보장되지는 않는다. 집필에 필요한 제약을 전달하고, 전체 canon을 참조하는 별도 검수와 연결하는 방안을 검토하라. 부정 지시가 반전을 암시하거나 표현을 과도하게 막을 위험도 고려하라.

11. 실행과 확정 절차

후보 흐름:
context 구성 → 회차 설계 → 초고 → 검수 → 사람의 수정 판단 → 최종 원고 후보 → 상태 변경안 → 원고와 변경안 확인 → 함께 확정.

다음 원칙을 검증하라.

* 모델이 낸 새 설정이 자동 canon이 되지 않는다.
* 상태 변화와 설정 변경을 구분한다.
* 검수자는 지적의 원문 근거를 제시한다.
* 지적에 인용문이 존재한다고 지적 자체가 옳은 것은 아니다.
* 수정된 최종 원고를 기준으로 상태를 추출한다.
* 같은 회차·같은 원고 버전이 다른 run으로 중복 반영되지 않게 한다.
* 승인한 뒤 원고가 바뀌면 기존 승인이 그대로 적용되지 않게 한다.
* 중간 실패 시 부분 반영을 식별하고 복구할 수 있어야 한다.
* Git 기록과 작업 파일의 일괄 반영을 같은 것으로 단정하지 않는다.

최소한의 식별자·원고 hash·반영 기록이 필요하면 사용한다. 과잉 설계를 피한다는 이유로 필요한 정합성 장치를 제거하지 마라.

Codex의 대화 resume와 집필 pipeline의 안전한 재개는 별개다. 여러 실행이 있다면 “마지막 세션”을 무조건 재개하는 위험도 검토하라.

12. 기술적 주장과 격리

Codex CLI 기능과 옵션은 가능하면 최신 공식 문서에서 확인하라. 확인한 사양, 설계 제안, 미확인 가정을 구분하라. 문서 확인이 불가능하면 그 사실을 밝히고 특정 옵션을 확정적으로 제시하지 마라.

작업 폴더 변경, 쓰기 제한, 읽기 제한, 네트워크 접근, 세션 기록은 서로 다른 문제다.

미래 정보 노출은 우선 서사 품질 문제다. 필요 이상으로 보안 인프라를 확대하지 마라. 강제 격리가 필요한 경우에만 컨테이너 등을 검토하고, 마운트뿐 아니라 접근 경로와 잔존 세션도 확인한다.

도구의 제공 기능만으로 이름 탐지, 비용 산정, 격리, 상태 정합성이 자동 보장된다고 주장하지 마라.

13. 검수와 실험의 원칙

자동 검사와 인간 판단을 분리한다.

자동 검사 후보:

* 파일·필수 항목 누락.
* 명시적인 ID와 표기 불일치.
* 글자수.
* 인용 문자열의 실존.
* 버전·중복 반영.
* 실제 입력 자료 목록.

모델 검수 후보:

선배, GitHub에 올렸으면 협업 단위는 자연스럽게 **PR = 회차**가 돼요. v3의 확정 절차(초고 → 검수 → 사람 판단 → 승인 → hash 결합 → 커밋)가 GitHub PR 흐름과 거의 1:1로 맞아서, 새 도구를 만들 게 별로 없어요. 아래는 그 매핑이고, 마지막에 어디서 깨질지 적었어요.

**1. 단위와 흐름**
- 회차 하나 = 브랜치 하나 = PR 하나. 초고, events.md 변경안, relations.md 변경을 같은 PR에 넣어요. merge가 곧 확정이고, merge commit이 hash예요.
- branch protection에 "새 커밋이 오면 기존 approve 무효화" 옵션을 켜면, v3에서 코드로 만들려던 "승인 후 원고가 바뀌면 승인이 안 따라간다"가 GitHub 기능으로 해결돼요.
- canon.md·style.md 변경은 회차 PR에 섞지 않고 별도 PR로, 선배와 형 둘 다 approve 필요(CODEOWNERS). 모델이 낸 새 설정이 자동 canon이 되지 않는다는 원칙이 여기서 강제돼요.

**2. 코멘트 규약 — 이게 핵심이에요**
협업자(형, 편집자)는 PR의 "Files changed"에서 줄 단위로 코멘트를 달아요. git을 몰라도 웹이나 모바일에서 돼요. 다만 코멘트 종류를 네 개로 고정해야 harness가 받을 수 있어요.
- `[정합성]` 이름·시간선·소유권·인물 지식 오류. **근거 회차와 원문 인용 필수.** 근거 없으면 harness가 무시하고 "근거 요청" 답글을 달아요.
- `[설정]` canon 변경 제안. 회차 PR에서 처리하지 않고 자동으로 Issue로 빠져 canon PR 후보가 돼요.
- `[문장]` 표현 수정. GitHub의 "suggested change" 기능을 쓰면 리뷰어가 직접 고친 문장을 제안하고 선배가 클릭 한 번으로 반영해요 — 모델을 거칠 필요가 없어요.
- `[재미]` 편집 의견. 자동 반영 절대 금지, 사람이 읽고 판단.

**3. 코멘트 → 수정의 자동화 범위**
harness가 PR의 리뷰 코멘트를 읽어(`gh api`) `[정합성]`만 골라 수정 지시로 묶고, 저장해 둔 세션 id로 `codex exec resume`을 돌려 같은 브랜치에 새 커밋을 올려요. 그러면 approve가 무효화되고 리뷰어가 다시 봐요. `[문장]`은 suggested change로 사람이 반영, `[설정]`·`[재미]`는 자동화에서 제외. 이 선을 넘으면 리뷰어가 "내 의견을 AI가 멋대로 고쳤다"고 느끼고 협업이 끊겨요.

**4. Actions에 올릴 것과 올리지 말 것**
- 올릴 것: v3의 자동 검사(글자수, 이름 사전 변형, `[정합성]` 코멘트의 인용 실존, run id 중복). PR 체크로 붙이면 리뷰어가 데이터 오류에 시간을 안 써요.
- 조건부: 모델 검수를 bot 코멘트로 다는 것. 되긴 하는데 API 키를 secret에 넣어야 하고 PR마다 비용이 나가요. 처음엔 로컬에서 돌려 결과를 선배가 코멘트로 옮기는 게 나아요.
- 올리지 말 것: merge 자동화. bot은 절대 merge하지 않아요.

**5. 회차 밖의 문제는 Issue**
회차 사이의 모순(3화와 7화가 충돌), 복선·독자 기대 추적, 설정 변경 제안은 Issue 템플릿 두 개로: `정합성 이슈`(근거 회차 A·B, 인용, 어느 쪽이 canon인가)와 `설정 변경`(현재 canon, 제안, 영향받는 회차). 이미 merge된 회차를 고쳐야 하면 Issue → 재개정 PR인데, 그 PR은 events.md의 해당 항목도 같이 바꿔야 통과되게 해요. 선배가 개인 태스크를 gh issues로 쓰고 계시니 여기까진 익숙한 도구예요.

**어디서 깨지나**
